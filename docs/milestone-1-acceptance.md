This record verifies the reference-preparation and alignment scope of [issue #1](https://github.com/micknudsen/oncohawk/issues/1) at implementation commit [`ef54b748c57414f8a4526877396f15c4718c516f`](https://github.com/micknudsen/oncohawk/commit/ef54b748c57414f8a4526877396f15c4718c516f). The commit-pinned evidence below describes the original implementation snapshot, before this migration.

## Acceptance boundary and operating constraints

The 2026-11-01 owner clarification in the child issues and [execution requirements](requirements.md#execution-environments) supersedes the original parent's proposed mandatory HPC verification. Full production-reference preparation/alignment and SLURM/Apptainer execution were **not performed** in this work. HPC access, run evidence, and sign-off are never formal acceptance gates. Cluster settings remain operator-configured, and site resource examples are illustrative allocations.

The [documented input contract](alignment.md#sample-sheet) requires safe identifiers/basenames, unique canonical FASTQ inputs, fresh output directories, and distinct sample names under case-insensitive comparison. Internal task names occupy a separate namespace to preserve staged sources. These are implemented validation rules with public regression coverage. Logs and metrics remain in task work directories; the published sample contract is one BAM and index per sample. Publication completes per sample, so an unsuccessful multi-sample run can already contain other completed samples.

Knowledge compilation, variant calling/reconciliation, annotation, and reporting remain outside milestone 1. This record establishes the tested workflow behavior and its acceptance evidence; it makes no claim of clinical validation.
